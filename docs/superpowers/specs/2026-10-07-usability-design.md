# EduMind 易用性优化方案

用户已选择轻量范围（2026-10-07）：仅实施新手说明、示例草稿、按钮与帮助文案、布局与可访问性；不实施完整备课表单、自动跳转、结构化产物预览、会话模型变更或后端改造。

面向第一次使用系统的教师及参与演示的团队成员。页面的首要任务是让用户快速说清一节课的需求，并找到可查看、可修改、可下载的教学材料。

## 现状问题

- 首屏以空对话与知识库为主，没有示例和明确的第一步。
- 上传、参考资料、语音入口仅显示图标；参考标记作用于下次上传，含义不明显。
- 追问粒度缺少说明，设置按钮没有功能，会话信息仍展示“开发中”。
- 单行输入不适合完整需求；生成后不会自动打开产物页。
- 产物面板主要提供下载，没有逐页课件和结构化教案预览。
- 上传不检查 HTTP 状态就报告成功；修改、互动生成和资料加载失败提示不充分。
- 会话切换与异步请求存在结果归属风险，生成试卷状态没有随会话可靠保存。
- 页面仅有桌面左右分栏布局，小屏无法方便操作。

## 推荐：有引导的备课工作台

### 首次使用与需求输入

首页显示“告诉我这节课怎么上”，三步真实流程：说明需求、补充资料（可选）、查看并修改材料。
提供三条可直接填入输入区的中文示例，不自动发送、不消耗 API。
简短备课表单只包含主题、年级、时长、教学重点和风格，填写后生成自然语言草稿，用户确认发送。
保留自由对话，多行输入支持 Enter 发送、Shift+Enter 换行，并防止中文输入法确认时误发送。
“快速/标准/精细”保留原值但补充解释，默认标准。

### 清晰的资料与结果入口

上传改为可读按钮，参考资料改为文字复选框，解释优先引用；列出真正支持的格式，避免宣称未实现的 .doc/.ppt。
上传反馈区分上传中、已收到、解析中、完成、失败，失败保留操作方向。
成功生成后自动打开产物预览；PPT 逐页展示标题与要点，Word 展示目标、重点、教学过程和作业。
PPT、Word、提纲为主要产物，试卷与互动内容为追加操作，下载与修改入口保持一致。
明确当前版本、来源资料和具体生成中状态，不显示虚假的进度百分比。
试卷按会话持久化，切换会话和刷新不出现另一节课的试卷。

### 系统帮助与错误处理

“使用帮助”提供可折叠的操作指南与当前服务状态；安全显示模型是否配置，不提供密钥内容。
说明真实文字/图片、本地检索、语音识别限制，区分浏览器语音输入与上传录音的演示转写。
所有请求统一检查状态并显示后端错误原因；失败不报告成功、不丢弃当前产物。
请求结果写回发起请求的会话，操作进行中禁止删除/切换，结束后正常恢复。
会话信息展示已知教学要素、材料状态和本地保存说明，移除未实现的提示。

### 视觉与可访问性

教学工作台以“课程任务卡”为核心视觉：清楚的主题与真实三步流程，不依赖装饰插画。
色彩：墨蓝 #17324D、教学蓝 #245EDB、淡蓝 #EDF3FF、纸白 #F7FAFE、边线 #DAE4EF、正文灰 #61758A。
字体：标题使用 Segoe UI Variable / Microsoft YaHei，正文使用 Segoe UI / PingFang SC / Microsoft YaHei，数字和步骤使用 Consolas。
桌面保留对话与材料双栏，小屏按纵向布局显示，控制区域可换行；键盘焦点可见、按钮有名称、禁用状态明确。

## 备选范围

1. 轻量优化：只增加按钮文案、示例和布局，改动少，但不能解决预览和异步会话问题。
2. 推荐工作台：上述完整闭环，保留现有核心结构和接口，逐步验证。
3. 严格向导：每次强制分步骤填写，适合统一流程，但会限制自由对话，不建议作为当前默认。

## 验证与交付

先使用模拟 API 的浏览器回归用例验证新手示例、表单草稿、失败反馈、产物预览、会话恢复、手机布局和中文输入法发送行为；验证前端构建与 lint、后端现有测试。
尽可能复用现有 API，不改已有云端供应商配置，不上传密钥，不推送 GitHub。
完成后保存桌面与手机截图、更新本机使用说明。必要时使用一次真实 DeepSeek 请求验证生成后的新流程，避免大量重复调用。
