# 会话材料隔离、资料删除与新建页面

## 用户要求

上传文件增加删除入口；不同备课会话的材料互不共享；删除全部会话后显示新建会话界面；该界面应比当前空对话更美观。

## 数据现状

会话只存在浏览器 localStorage 中；Document、知识节点、冲突与向量索引为全局数据；所有会话备课都会检索全部文档。课件/教案以会话存储，试卷目前仅为预览组件状态。删除最后一个会话会调用 freshStore 自动创建会话。
因此隔离必须落实到服务端查询与生成上下文，不能只隐藏其他会话的文件列表。

## 实施方案

### 文件删除

每份资料右侧提供删除按钮，确认时显示文件名和影响。删除只允许操作当前会话所属资料。
清理文档记录、上传原文件、相应文本片段及向量、由该资料独占的知识点/关联和待审核差异，确保删除资料不再被检索采用。处理中的资料禁止立即删除，界面解释需等待解析结束。
删除操作失败显示原因，不先从界面假移除；测试使用临时资料，不删除本机既有资料。

### 会话隔离

文档及相关记录增加稳定的 session_id；浏览器会话 id 随上传、列表、删除、检索、备课、试卷和互动生成请求发送。
备课检索限制当前会话文档，知识点关联扩展、冲突比较与审核均在同一归属范围内。不能检索到其他会话内容后再仅在界面过滤。
课件、教案、试卷与互动材料按会话保存；切换/刷新后显示各自版本，不显示上一会话的试卷。生成结果写回发起请求的会话，繁忙期间禁止删除会话。
删除会话时明确告知会一并清理其上传资料和对应索引，保留用户已下载到电脑的文件。服务端生成文件需要记录会话归属并核对下载归属。

### 全部删除后的新建界面

会话存储支持零会话，刷新后仍保持零会话；不再自动生成隐形会话。
零会话时显示独立的欢迎页，隐藏空聊天、输入区和材料列表。用户点击“新建备课”或示例课程卡后才创建会话。
入口可给课程命名；示例课程创建会话并填入需求草稿，仍由用户确认发送，不自动消耗 API。

### 视觉方向

沿用已优化的墨蓝与教学蓝，以展开的“备课任务卡”为独特元素。页面左侧用简洁的主标题、流程和用途说明，右侧展示带课程名输入的新建卡片；下方放三张不同学科的示例卡。
采用纸白底色、淡蓝内容层、清晰字号与留白，小幅阴影强调可交互卡片；没有功能的控件不出现。桌面为双栏，手机为纵向单栏；明确键盘焦点、输入标签和减少动画支持。

## 历史资料迁移（待用户确定）

推荐把尚未归属的旧上传资料一次性归入当前选中的会话，保留已有内容。之后创建的会话为独立空知识库。
另一方案是新建“以前的资料”会话，将旧资料集中存放，原有会话仅保留各自生成材料。
迁移前备份开发数据库和索引；迁移只增加归属，不删除旧上传资料。

## 验收

后端用两个会话和两套独立资料验证列表、检索、图谱、冲突及生成上下文隔离，验证跨会话删除/下载被拒绝；验证删除后资料与索引不残留。
浏览器验证文件删除确认、失败提示、切换会话材料独立、试卷刷新恢复、最后一个会话删除后落到欢迎页且刷新保持、新建与示例入口、桌面和手机无溢出。
再运行完整后端测试、前端构建与隔离浏览器回归。必要的 API 兼容调整同步更新既有测试和运行说明。
